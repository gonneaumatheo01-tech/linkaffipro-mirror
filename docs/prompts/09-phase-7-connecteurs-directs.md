# Phase 7 — Connexions directes depuis la plateforme : comptes publicitaires (Meta, TikTok) et vues Telegram

Lis `CLAUDE.md` (dont « Mode autonome » et « Communication par Telegram »), `docs/STATUS.md`, `docs/A-FAIRE-HUMAIN.md`, `docs/02-decisions.md`, puis les docs officielles à jour (WebFetch) : Meta Marketing API (Facebook Login, permissions `ads_read`, Insights API, jetons longue durée, mode développement vs live, Standard vs Advanced Access, App Review) et TikTok Marketing API (OAuth 2.0, `advertiser/get`, Reporting API `report/integrated/get`, sandbox, validation d'app). Décide seul, note dans `docs/DECISIONS-TECH.md`, enchaîne sans question.

**Objectif.** L'utilisateur branche lui-même, depuis Réglages → Connecteurs, autant de comptes publicitaires qu'il veut (Meta Ads, TikTok Ads, plusieurs comptes et plusieurs Business Manager), sans Claude Code ni assistance : un bouton « Connecter un compte », une connexion chez Meta ou TikTok, une liste de comptes à cocher, et les dépenses arrivent toutes seules dans le module Pubs. Même principe pour les vues Telegram par message : il saisit son numéro et le code SMS dans la plateforme. La seule action humaine incompressible est la création d'une app développeur chez Meta et chez TikTok : la page Connecteurs doit l'expliquer clic par clic, avec les valeurs exactes à copier-coller (adresses de redirection, domaines, permissions), pour que l'utilisateur la fasse seul en 10 minutes.

## 1. Réglages → Connecteurs → « Applications » (une fois par plateforme)
- Formulaire par plateforme : Meta (App ID, App Secret), TikTok (App ID, Secret). Valeurs chiffrées en base (AES-256-GCM, comme les jetons de bots). Bouton « Vérifier » qui teste les identifiants sans rien connecter.
- Sous chaque formulaire, un guide pas à pas en français simple, écrit pour quelqu'un qui n'a jamais vu ces outils, avec les valeurs exactes à coller affichées dans des champs « Copier » :
  - Meta : developers.facebook.com → Créer une app (type Business) → ajouter le produit « Facebook Login for Business » (ou « Facebook Login » selon la doc à jour) → URI de redirection OAuth valides = `https://app.linkaffipro.com/api/connectors/meta/callback` → domaine de l'app → Paramètres de base : App ID et App Secret → ajouter les membres de l'équipe comme « Testeurs / Développeurs » de l'app (en mode développement, seuls ces rôles peuvent se connecter ; expliquer que cela suffit pour tous les comptes que le profil Facebook de la personne peut voir) → quand il faudra laisser d'autres personnes connecter leurs propres comptes : passage en mode Live, URL de politique de confidentialité (crée une page `/privacy` sur le site), App Review pour `ads_read` et vérification d'entreprise ; décris-le comme une étape « plus tard, seulement si besoin ».
  - TikTok : business-api.tiktok.com → compte développeur → Créer une app (Marketing API) → URL de redirection = `https://app.linkaffipro.com/api/connectors/tiktok/callback` → permissions « Ad Account Management » et « Reporting » (noms exacts selon la doc) → soumettre à validation (1 à 2 semaines) → App ID et Secret. Expliquer que la connexion de comptes réels n'est possible qu'après validation, et proposer le mode sandbox pour vérifier le branchement en attendant.
- Les deux guides sont aussi recopiés dans `docs/GUIDE-UTILISATEUR.md` (section Connecteurs) et résumés dans `docs/A-FAIRE-HUMAIN.md` (« créer les deux apps », avec le temps estimé).

## 2. Connexion des comptes (OAuth, multi-comptes)
- Meta : bouton « Connecter un compte Meta » → Facebook Login (scopes `ads_read`, `business_management` si nécessaire pour lister les Business Manager) → callback → échange contre un jeton utilisateur longue durée → liste des comptes publicitaires accessibles (`me/adaccounts` avec nom, identifiant, devise, statut, Business Manager) → l'utilisateur coche ceux à connecter → enregistrement (`AdAccountConnection` : plateforme, identifiant externe, nom, devise, fuseau, jeton chiffré, utilisateur qui a connecté, statut, dernière synchro, erreur). Rafraîchissement du jeton avant expiration ; si la connexion expire ou est révoquée : statut « À reconnecter » + alerte Telegram + bouton « Reconnecter ».
- TikTok : bouton « Connecter un compte TikTok » → OAuth → `oauth2/access_token` → liste des advertisers autorisés (`oauth2/advertiser/get`) → cocher → enregistrement identique. Gestion du refresh si la doc le prévoit, sinon reconnexion guidée.
- Plusieurs comptes par plateforme, plusieurs connexions par utilisateur, et des comptes connectés par des utilisateurs différents (chaque admin ou manager peut connecter les comptes qu'il voit). Déconnexion d'un compte en un clic (le jeton est supprimé ; les coûts déjà importés restent).

## 3. Synchronisation des dépenses et des performances
- Worker `sync-ads` : toutes les heures pour la veille et le jour en cours (les plateformes recalculent les chiffres a posteriori : resynchroniser les 3 derniers jours à chaque passage, et les 28 derniers jours une fois par nuit), à la création d'une connexion : historique des 90 derniers jours.
- Niveaux : campagne, groupe de pubs, pub ; métriques : dépense, impressions, clics, CPM, CPC, CTR, portée si disponible, résultats de la plateforme ; par jour, par compte, en devise du compte et convertie en EUR (`currency_rates` Link Affi ou taux saisis). Les entités (campagnes, groupes, pubs) sont créées ou mises à jour dans le module Pubs existant, reliées automatiquement aux liens d'entrée par la convention de nommage déjà en place (sinon suggestion de liaison à confirmer d'un clic).
- L'import CSV reste disponible comme secours ; une pub connectée par API n'accepte plus de doublon par CSV (priorité à l'API, règle visible).
- Limites de débit et erreurs : respecter les quotas (Meta : gestion des codes d'erreur de limitation ; TikTok : limites de requêtes), reprises avec attente croissante, journal par connexion visible dans Connecteurs (dernière synchro, lignes importées, erreur lisible).
- Tableau de bord et onglet Pubs : CPL, CPA, coût par FTD, ROAS et bénéfice utilisent ces coûts automatiquement ; indiquer la source (API ou CSV) sur chaque ligne.

## 4. Vues Telegram par message (MTProto) depuis la plateforme
- Réglages → Connecteurs → « Telegram (vues et transferts) » : formulaire numéro de téléphone → code reçu dans Telegram → mot de passe de validation en deux étapes si activé → session enregistrée chiffrée (GramJS, `StringSession`). Explication en une ligne de ce que ça autorise, bouton « Déconnecter » qui révoque la session. Un seul compte suffit (le propriétaire des canaux) ; il doit être administrateur des canaux.
- Worker `sync-views` : pour chaque message envoyé par la plateforme (et les posts du canal des 30 derniers jours), récupérer vues et transferts (`channels.getMessages` / `messages.getMessagesViews`), toutes les 15 minutes pendant 48 h après l'envoi puis une fois par jour pendant 30 jours ; stockage dans `PostStats.views`, `forwards`, et historique par relevé pour les courbes. Respecter les limites MTProto (attente sur `FLOOD_WAIT`), un seul client, pas de parallélisme.
- Utilisations : taux de clic par vue, meilleurs horaires et tests A/B basés sur les vues quand elles existent (sinon clics et réactions, comme aujourd'hui), affichage dans la fiche message, le calendrier et la comparaison par catégorie.

## 5. Sécurité et conformité
- Jetons et sessions chiffrés, jamais journalisés, jamais exportés ; accès ADMIN pour connecter ou déconnecter, MANAGER en lecture. Journal d'audit pour chaque connexion, déconnexion et synchro manuelle.
- Page publique `/privacy` (politique de confidentialité en français, simple, nécessaire pour Meta) et `/terms` si la doc Meta ou TikTok l'exige.
- Révocation : si la plateforme renvoie une erreur de jeton, marquer « À reconnecter », ne pas boucler.

## 6. Tests et livraison
- Tests unitaires sur la logique (mapping des rapports, conversion devise, résolution des liaisons pub ↔ lien d'entrée, chiffrement, machine à états des connexions) avec réponses d'API simulées ; tests d'intégration des callbacks OAuth avec des jetons factices ; aucun appel réel à Meta ou TikTok sans identifiants (les identifiants d'app n'existent pas encore : tout doit être prêt à fonctionner dès qu'ils seront saisis, avec le bouton « Vérifier »).
- Sandbox TikTok si disponible sans validation : l'utiliser pour un test de bout en bout, sinon simuler.
- `pnpm lint && pnpm build && pnpm test` verts, déploiement vérifié, `docs/STATUS.md`, `docs/A-FAIRE-HUMAIN.md` (les deux apps à créer, avec le temps estimé et le lien direct vers la page Connecteurs), `docs/GUIDE-UTILISATEUR.md` et `CLAUDE.md` à jour, commit et push.
