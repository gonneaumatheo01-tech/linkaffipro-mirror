# Phase 1 — Kit de lancement (à exécuter en entier, en autonomie)

Pré-requis : la phase 0 est terminée (`docs/STATUS.md` le confirme et l'utilisateur a dit « phase 0 OK »). Lis `CLAUDE.md`, `docs/02-decisions.md`, `docs/DATA-MODEL.md`, `docs/LINKAFFI-SCHEMA.md`, `docs/DECISIONS-TECH.md`. Puis exécute les sections dans l'ordre, avec une liste de tâches. Les sections 1 à 6 sont indispensables avant d'allumer les pubs ; 7 à 9 viennent ensuite, dans la même phase.

**Objectif de la phase.** L'équipe peut allumer les pubs. Chaque pub a son lien goolink et son lien d'invitation Telegram. Les demandes d'adhésion sont accueillies par le bon bot, filtrées par le flux « rejoins ces canaux », puis acceptées après le délai réglé canal par canal. Les messages sont programmés depuis un calendrier. Chaque clic « offre » génère un sub-ID par membre et par message, transmis à Link Affi. Les événements Link Affi (inscription, FTD, dépôts, NGR) remontent sur la fiche du membre.

**Principes.** Interface en français, simple, lisible par un manager pressé : une action principale par page, des textes d'aide d'une ligne, des valeurs par défaut sensées. Tout est journalisé dans `Event` et `AuditLog`. Rien ne part vers Telegram sans passer par la file d'attente et ses limites. Tests unitaires sur la logique, tests d'intégration sur les routes et les workers.

## 2. Flux « demande d'adhésion » (le cœur du kit)

1. Le bot reçoit `chat_join_request` (canal, utilisateur, `invite_link`, `user_chat_id`). Upsert `Member`. Résous `InviteLink` par le lien. Crée `Membership` en `REQUESTED` avec le snapshot de source. `Event` `membership.requested`.
2. Résous la règle : règle du lien si elle existe, sinon la règle par défaut du canal, sinon une règle implicite `DELAY 0, NONE`. Le bot qui agit est le bot principal du canal ; s'il n'est pas administrateur, utilise n'importe quel bot administrateur du canal et journalise un avertissement.
3. Envoie immédiatement le message d'accueil (séquence `JOIN_REQUEST`) en message privé via `user_chat_id`, dans la langue du membre si une traduction existe, sinon la langue du canal, sinon fr. Si l'envoi échoue (fenêtre expirée, bot bloqué) : `MemberBotState.canDm = false`, `Event` `dm.failed`, et on continue avec la règle sans gate (approbation selon le délai) ; ne jamais bloquer un membre à cause d'un DM impossible, sauf si `gateMode = REQUIRED` et `expireAfterHours` est défini (alors `EXPIRED` à l'échéance avec l'action prévue).
4. Gate `REQUIRED` ou `SOFT` : le message d'accueil contient un bouton URL par canal à rejoindre (lien d'invitation de type `GATE` créé par la plateforme pour ce canal, sans demande d'adhésion sauf réglage contraire ; un lien GATE par couple canal source → canal requis, pour savoir d'où vient le membre) et un bouton « ✅ J'ai rejoint » qui ouvre `https://t.me/<bot>?start=g<code membership>`. Statut `PENDING_GATE`.
5. Handler `/start g<code>` : vérifie chaque canal requis avec `getChatMember` (statuts acceptés : member, administrator, creator). Tous rejoints : `gateSatisfiedAt`, `approveAt = now + delaySeconds`, statut `SCHEDULED`, réponse « C'est bon, tu seras accepté dans {délai} » (ou approbation immédiate si délai 0). Sinon : réponse listant les canaux manquants avec les mêmes boutons. Chaque `/start` marque `canDm = true`.
6. Sans gate : `approveAt = requestedAt + delaySeconds`, statut `SCHEDULED` (ou `MANUAL` : reste `REQUESTED` et apparaît dans une file « à valider » dans l'interface avec boutons Accepter / Refuser).
7. Worker `approvals` : toutes les 20 secondes, `SELECT ... FOR UPDATE SKIP LOCKED` des `Membership` `SCHEDULED` dont `approveAt <= now`, puis `approveChatJoinRequest` via la file Telegram. Succès : `APPROVED`, `Event`, message « accepté » si `sendAcceptedMessage`. Erreurs Telegram « USER_ALREADY_PARTICIPANT » → `APPROVED` ; « HIDE_REQUESTER_MISSING » (demande retirée) → `EXPIRED` ; autre erreur → 3 tentatives puis `FAILED` journalisé et visible dans l'interface.
8. Rappels : worker toutes les 5 minutes pour les `PENDING_GATE` selon `reminderAfterMinutes` et `maxReminders`, uniquement si `canDm`. Expiration selon `expireAfterHours`.
9. `chat_member` (le bot doit être administrateur et `chat_member` doit être dans `allowed_updates`) : entrée effective → `joined` sur le `Membership` et `Event` `membership.joined` (avec `invite_link` pour l'attribution des liens GATE) ; départ → `LEFT` ; exclusion → `KICKED`. Un membre qui revient crée un nouveau `Membership`.
10. Interface Canaux → un canal → onglet « Règles d'adhésion » : éditeur simple (mode, délai avec sélecteur « immédiat / 1 minute / 10 minutes / 1 heure / 1 jour / 2 jours / personnalisé », canaux à rejoindre, mode du gate, rappels, expiration, message accepté oui/non) ; onglet « Demandes » (liste en temps réel avec statut, source, temps restant, actions Accepter maintenant / Refuser) ; onglet « Membres ».

## 3. Liens : entrée par pub, offres personnalisées, boutons traqués

- Page **Liens** → « Nouveau lien d'entrée (pub) » : canal, nom (ex. `TT-casino-FR-video3`), plateforme (TikTok / Meta / Autre), noms de campagne / groupe / pub, langue, règle d'adhésion à appliquer (optionnel). Création : lien d'invitation Telegram `createChatInviteLink` avec `creates_join_request = true` et `name = nom` par le bot principal du canal ; `TrackingLink` kind `AD_ENTRY` dont la destination est ce lien t.me ; affichage de « l'URL à coller dans la pub » avec les macros par plateforme : TikTok `https://goolink.eu/<slug>?ttclid=__CLICKID__&utm_source=tiktok&utm_campaign={{campaign.name}}` (vérifie les macros officielles TikTok et Meta dans leur documentation et utilise les bonnes), Meta `https://goolink.eu/<slug>?utm_source=meta` (le fbclid est ajouté par Meta). Bouton « copier ». Possibilité de créer plusieurs liens d'un coup (une ligne par nom).
- Redirection `GET goolink.eu/<slug>` : 302 immédiat vers la destination ; `Click` enregistré (anonyme pour AD_ENTRY) avec ttclid / fbclid / utm ; dédoublonnage 10 secondes par (ipHash, userAgent, slug) ; robots marqués et non comptés dans les stats ; `Cache-Control: no-store`. Temps de réponse visé < 50 ms (requête unique, index sur slug, pas de rendu).
- Offres personnalisées : un bouton de post de type `OFFER` pointe vers `https://t.me/<bot>?start=o<code TrackingLink>_<code Post>` (charge utile ≤ 64 caractères, alphabet `A-Za-z0-9_-`). Handler `/start o…` : upsert `Member`, `Click` avec `subId` neuf, `memberId`, `postId`, `botId` ; construit l'URL finale à partir de `AffiliateCampaign.trackingUrlTemplate` (placeholder du sub-ID conforme à `docs/LINKAFFI-SCHEMA.md`) ; répond par la séquence `OFFER_REPLY` (texte court + bouton URL « Ouvrir l'offre ») ; `canDm = true`. Si le membre reclique, nouveau `Click` et nouveau sub-ID (on garde l'historique).
- Boutons `BUTTON` (URL traquée anonyme) : la plateforme crée un `TrackingLink` kind `BUTTON` rattaché au post ; destination = l'URL saisie ; comptage par clic.
- Page **Liens** : tableaux séparés Entrées / Offres / Boutons avec clics, clics uniques, demandes, acceptés, inscriptions, FTD (quand les données Link Affi existent), bouton copier, désactiver.

## 4. Messages programmés (calendrier)

- Page **Messages** : vue calendrier (semaine, avec jours et heures, Europe/Paris) + vue liste filtrable (canal, statut, catégorie, période). Bouton « Nouveau message ».
- Formulaire : canaux (multi-sélection → un `Post` par canal, liés par `duplicatedFromId`), date et heure, catégorie, texte (éditeur avec gras, italique, souligné, lien, émoji, aperçu Telegram en direct ; stocké en HTML Telegram, validé), médias (glisser-déposer, image / vidéo / gif / document, ordre, aperçu ; stockés en `MediaAsset`), boutons (lignes de boutons : libellé + type `URL` / `BUTTON` traqué / `OFFER` avec choix de la campagne Link Affi), options (épingler après envoi, désépingler le précédent, supprimer après N minutes, silencieux, contenu protégé, sans aperçu de lien), enregistrer en brouillon ou programmer. Dupliquer un message, le décaler, l'annuler, le supprimer sur Telegram.
- Contraintes Telegram à respecter : un album (`sendMediaGroup`) ne peut pas porter de boutons → envoyer l'album puis un message texte avec les boutons, ou une photo seule avec légende et boutons ; légende ≤ 1024 caractères, texte ≤ 4096 ; HTML Telegram seulement (b, i, u, s, a, code, pre, tg-spoiler, blockquote).
- Worker `scheduler` : toutes les 30 secondes, réclame les `Post` `SCHEDULED` échus (`FOR UPDATE SKIP LOCKED`), passe en `SENDING`, enfile un job `send-post` (jobId = postId, idempotent). Worker `telegram-send` : limiteur par bot (25/s) et par chat (1/s pour les messages privés, 20/minute vers un même canal) ; envoi ; `SENT` avec identifiants de messages ; épinglage ; planification de la suppression ; `Event` `post.sent`. Erreur 429 : respecter `retry_after` ; erreur réseau : 3 tentatives avec attente croissante ; erreur 400 : `FAILED` avec message lisible dans l'interface (« texte trop long », « bot non administrateur », …).
- Réactions : traiter `message_reaction_count` pour mettre à jour `PostStats.reactions`. Les vues viennent en phase 2.
- Modèles : « enregistrer comme modèle » et « nouveau depuis un modèle ».

## 5. Synchronisation Link Affi (API en lecture seule)

- Worker `sync-linkaffi` toutes les 2 minutes, via le client de l'API créé en phase 0 (`docs/LINKAFFI-API.md`, `docs/LINKAFFI-SCHEMA.md`). Importe : `casinos` → `AffiliateProgram` ; `campaigns` → `AffiliateCampaign` (avec `trackingUrlTemplate` et le placeholder du sub-ID) ; `clicks` → rattachement par sub-ID ; `players`, `player_events`, `player_financials`, `ftd_invalidations` → `Player` et `PlayerEvent` (clic, inscription, FTD, dépôts, redépôts, NGR) ; `currency_rates` → montants convertis en EUR. Incrémental par fenêtre de dates (`date_col` de mise à jour quand elle existe, sinon création) avec chevauchement de 15 minutes, curseur dans `SyncState`, idempotent (upsert par identifiants externes), tolérant aux colonnes manquantes selon le programme. Première synchronisation : tout l'historique, en tâche de fond avec reprise. Une requête par seconde maximum, `limit=5000`, pagination par `offset`.
- Rattachement : `Player.subId` → `Click.subId` → `memberId`, `postId`, `channelId`, `trackingLinkId` ; mise à jour de `PostStats` et des compteurs dénormalisés ; `Event` `player.registered`, `player.ftd`, `player.deposit`, `player.ngr_updated` avec `memberId` quand connu.
- Uniquement des GET. Jamais d'écriture, jamais les tables marquées « à ne pas lire ». Documente la correspondance exacte dans `docs/LINKAFFI-SYNC.md`. Page Réglages → Connecteurs : état de la synchro par table (dernière exécution, lignes importées, erreur), bouton « synchroniser maintenant ».
- Niveau de dépense d'un membre (calculé, affiché sur la fiche) : `AUCUN` (pas de joueur rattaché), `INSCRIT` (inscription sans dépôt), `DÉPOSANT` (FTD), `RÉGULIER` (≥ 3 dépôts), `VIP` (dépôts cumulés au-dessus d'un seuil réglable dans Réglages, par défaut 500 €). Seuils modifiables.

## 7. Séquences d'accueil multilingues

- Pour chaque canal détecté : séquences par défaut `JOIN_REQUEST`, `GATE_REMINDER`, `GATE_SATISFIED`, `APPROVED`, `OFFER_REPLY`, en français, avec placeholders `{prenom}`, `{canal}`, `{liste_canaux}`, `{delai}`, `{bot}`. Propose des textes courts, chaleureux, sans promesse de gains, adaptés à l'univers (casino, paris, dating). Exemple JOIN_REQUEST casino : « Salut {prenom} ! Pour rejoindre {canal}, rejoins d'abord nos canaux partenaires ci-dessous, puis appuie sur ✅ J'ai rejoint. Ton accès est validé {delai}. »
- Page Canaux → un canal → onglet « Messages du bot » : édition par langue (fr obligatoire, ajout d'une langue en un clic : en, es, pt, de, it, ar, tr…), aperçu, « envoyer un test » à l'utilisateur connecté s'il a lié son Telegram (`User.telegramUserId`, voir « Mon compte »).
- Choix de la langue d'un membre : `Member.languageCode` si la séquence a cette langue, sinon langue du canal, sinon fr.
